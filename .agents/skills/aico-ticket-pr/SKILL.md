# aico-ticket-pr

## 目的

作業ブランチの変更内容とチケット記録から、GitHub PR / GitLab MR の作成画面へそのまま貼り付けられる Title と Description（Markdown）を生成して出力する。リモートへの push や PR/MR の自動作成自体は行わない。  
本スキルは**完全オプショナル**であり、ローカルマージ運用や複数の PR/MR テンプレートを使い分けるプロジェクトでは利用しなくても AIco の全ワークフローを完結できる。

## 入力

* 対象チケット ID（省略可）
* 比較先ブランチ（省略時は `aico-manifest.json` の `integration_branch`）
* 使用するテンプレートファイルパス（任意）
* 対象 ID の指定が省略された場合は、以下の3段階フォールバックで解決する。
1. ユーザーの明示指定（ID・`slug`・パス）。
2. `uv run <管理ルート>/scripts/ticket_status.py --json` による現在の Git ブランチと `branch` 属性の照合。
3. 自動特定できない場合は該当状態の候補一覧を提示して人間に選択してもらう。

## 前提条件

* 比較先ブランチとの差分（または未マージコミット）が存在すること。

## 手順

1. 対象チケットが特定できた場合は、`index.md`（概要・AC・DoD・変更ファイル・関連議事録／ADR）および `plan.md`（合意仕様・検証方針・判断ログ）を読み込む（チケットに紐づかない作業ブランチの場合は差分とコミット履歴のみで進める）。
2. 比較先ブランチとの `git diff --name-status`・主要差分および `git log` を実物照合し、記録内容と実装差分に食い違いがないか確認する（差分要約・文面生成は推奨ワーカー `worker-middle` または `worker-low` へ委譲可）。  
   サブエージェントワーカーへ委譲する際は、親セッションの会話履歴が引き継がれない前提で、必ず以下の5項目をプロンプトへ明示する。
1. 参照する手順書・スキルパス
2. 対象範囲（ファイル・調査対象・比較基点コミット等）
3. 入力条件・制約（前提条件・対象外・守るべき規約）
4. 変更可否（読み取り専用か、許可する編集範囲はどこか）
5. 期待する成果と報告形式（出力先パス・実行環境・未確認事項を含む）
3. 以下の優先順で Description のテンプレートを決定する。
   1. ユーザーが明示指定したテンプレートファイル
   2. `aico-manifest.json` の `pr_template`（非空かつ実ファイルが存在する場合）
   3. AIco 標準構成（概要 / 主な変更内容 / 検証結果・未確認事項 / 関連チケット・ADR・議事録 / レビュー観点）
4. `aico-markdown-write` に従い、実物差分・検証結果と整合した Title と Description を生成する。テンプレート内に確認チェックリストがある場合でも、実物確認・検証が完了していない項目には勝手にチェック（`[x]`）を入れず `[ ]` のまま残し、未確認事項として明記する。

## 完了条件と状態更新

* 実物差分と整合した PR/MR 用 Title と Description が出力されていること。
* 状態変更・push・PR/MR 作成操作は行わない。

## 報告形式

* PR/MR 作成画面へそのまま転記できる Title および Description（Markdown ブロック）
