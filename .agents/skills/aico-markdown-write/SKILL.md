# aico-markdown-write

## 目的

管理記録および関連文書の可読性と構造の一貫性を保つため、作成・編集時に守るべき Markdown 規約を適用する。

## 入力

* 作成または編集対象の Markdown 文書（任意）

## 前提条件

* 管理記録（議事録・ADR・チケット配下の全記録・Runbook 手順書および実施記録）の作成・編集時は本スキルを必ず適用する。
* 導入先固有のシステム設計書や README 等は、`AGENTS.md` マーカー外に別段の定めがない限り適用を推奨する。

## 手順

1. 作成・編集前に文書の全体構成（見出し階層と結論の配置）を決め、冒頭に概要を置いて全体像を先に示し、詳細を後ろの節へ配置する。
2. 以下のチェックリストに従って本文を作成・推敲する。
   * **文字コード・改行**：UTF-8（BOM なし）・LF 改行とする。段落内や箇条書き継続行で強制改行する場合は、GitHub・GitLab 等で文が連結されないよう行末へ半角スペース2個を付ける。
   * **見出し構造**：H1（`#`）は文書タイトル1つのみとし、見出しレベルを飛ばさない（`#` → `##` → `###`）。
   * **文体の統一**：管理記録・仕様・ポリシーは常体（だ・である調）で統一し、同一文書内で敬体と混在させない。
   * **箇条書き・表**：同一ファイル内で箇条書き記号（`* ` 等）を統一する。表セル内で複数項目を縦に並べる場合は `・` と `<br>` を用いる。
   * **コード・図**：コードブロックには必ず言語識別子（`text`, `json`, `python`, `bash`, `mermaid` 等）を明記する。Mermaid 図のラベルに括弧等を含む場合は二重引用符で囲む。
   * **リンク・参照**：管理記録間の本文リンクは標準 Markdown の相対リンクを用い、frontmatter には移動に強い不変 ID を用いる。
   * **構成の明快さ**：1文1義を心がけ、結論を先に書き、重複表現や不要な装飾を避ける。
3. 編集完了後、見出し飛び・コードブロック言語指定漏れ・リンク切れがないことを目視または `doctor.py` で確認する。

## 完了条件と状態更新

* すべてのチェックリスト項目を満たして保存されていること。
* ステータス等の frontmatter 状態更新は行わない。

## 報告形式

* 適用した対象ファイルパスと、主な構造・表記の整備要点を簡潔に報告する。
