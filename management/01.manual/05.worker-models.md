# 05. おすすめ `worker_models` 設定例

## 概要

AIco の 3 段階ワーカー（`worker-high`・`worker-middle`・`worker-low`）に対して、4 ツール別のおすすめモデル設定例をまとめています。  
**最終確認日：2026-11-24**

※`worker_models` は初期状態ではすべて空欄（`""`）になっています。**空欄のままでも各ツールの既定モデルでそのまま動作する**ため、最初は未設定で使い始め、慣れてきたタイミングで設定しても問題ありません。

## 3 段階ワーカーの使い分け

| ワーカー | 主に任せる作業 | 選定の目安 |
| :--- | :--- | :--- |
| **`worker-high`** | 深い調査、複雑な設計判断、重要なレビュー、難しい原因分析 | 精度と推論力を最優先 |
| **`worker-middle`** | 通常の実装、一般的な独立レビュー、定型外の修正 | 精度・速度・コストのバランス |
| **`worker-low`** | 既存記録の横断確認、定型処理、ログ抽出、定型報告 | 速度とコストを優先 |

## ツール別おすすめ設定（2026-11-24 時点）

| ツール | `high`（model / effort） | `middle`（model / effort） | `low`（model / effort） | 補足 |
| :--- | :--- | :--- | :--- | :--- |
| **Claude Code** | `opus` / `high` | `sonnet` / `high` | `haiku` / `high` | 公式エイリアスを使用するため版更新に強い（特定版に固定したい場合は `claude-opus-5-5` 等の ID も指定可） |
| **Codex** | `gpt-6.2-astra` / `high` | `gpt-6.2-sol` / `medium` | `gpt-6.2-sol` / `low` | 高難度推論は Astra、通常実装・軽量処理は Sol を `effort` で使い分け |
| **Antigravity** | `pro` / `""` | `flash` / `""` | `flash_lite` / `""` | Antigravity のサブエージェントは抽象ティア（`pro`・`flash`・`flash_lite`・`inherit`）のみ受理し、`effort` は使用しない |
| **GitHub Copilot（VS Code）** | `gemini-4-neon` / `high` | `claude-opus-5.5` / `medium` | `gpt-6.2-sol` / `low` | Copilot 上の Claude Opus 5.5 はドット区切り（`claude-opus-5.5`）。同期時に `reasoning-effort` として出力される |

## `management/aico-manifest.json` 記入例（コピペ用）

利用しているツールのブロックだけを `management/aico-manifest.json` の `worker_models` へ転記して使ってください。

```json
"worker_models": {
  "claude": {
    "high": { "model": "opus", "effort": "high" },
    "middle": { "model": "sonnet", "effort": "high" },
    "low": { "model": "haiku", "effort": "high" }
  },
  "codex": {
    "high": { "model": "gpt-6.2-astra", "effort": "high" },
    "middle": { "model": "gpt-6.2-sol", "effort": "medium" },
    "low": { "model": "gpt-6.2-sol", "effort": "low" }
  },
  "antigravity": {
    "high": { "model": "pro", "effort": "" },
    "middle": { "model": "flash", "effort": "" },
    "low": { "model": "flash_lite", "effort": "" }
  },
  "copilot": {
    "high": { "model": "gemini-4-neon", "effort": "high" },
    "middle": { "model": "claude-opus-5.5", "effort": "medium" },
    "low": { "model": "gpt-6.2-sol", "effort": "low" }
  }
}
```

## 設定の反映手順

`management/aico-manifest.json` を編集したら、プロジェクトルートで次を実行して各ツールのワーカー定義へ反映します。

```bash
tools/aico.sh sync_agents
tools/aico.sh doctor
```

Windows 環境では `tools\aico.bat sync_agents` および `tools\aico.bat doctor` を実行してください。

## 環境ごとに確認したいときのヒント

契約プランや組織ポリシーによって利用できるモデル ID が異なる場合があります。エラーが出たときは、各ツールの確認方法で有効なモデル ID を調べて差し替えてください。

* **Claude Code**：セッション内の `/model` で利用可能モデルを確認できます。
* **Codex**：ターミナルで `codex debug models` を実行すると利用可能なモデル一覧を確認できます。
* **Antigravity**：サブエージェントでは `pro` / `flash` / `flash_lite` / `inherit` のいずれかを指定してください（具体モデル ID を直接書くとエラーになります）。
* **GitHub Copilot（VS Code）**：`.github/agents/worker-high.agent.md` を VS Code で開き、`model:` の行で入力補完（Ctrl+Space）を使うと、自分の契約プランで有効なランタイムモデル ID を確認できます。

設定が終わったら [Getting Started](01.getting-started.md) に戻るか、[チュートリアル](02.tutorial.md) で最初の 1 チケットを試してみてください。
