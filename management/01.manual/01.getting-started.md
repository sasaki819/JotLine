# 01. Getting Started（導入と初期設定）

## 概要

既存または新規の Git プロジェクトへ AIco を導入し、AI エージェントと一緒に使い始められる状態にするまでの手順です。  
すでに導入済みのプロジェクトへ参加した方は、プロジェクトルートの `AGENTS.md` を確認したうえで [チュートリアル](02.tutorial.md) からご覧ください。

## 前提環境

導入前に、手元の環境に以下が揃っていることを確認してください。

* **Git**：リポジトリのルートディレクトリで操作できること
* **Python 3.11 以上**（`uv` が入っていればワンライナーで導入できます）
* **対応 AI ツール（いずれか 1 つ以上）**：Claude Code、Codex、Antigravity、GitHub Copilot（VS Code）

※AIco は既存プロジェクトのソースコードや既存の `AGENTS.md` 本文を上書きせず、専用ディレクトリとマーカー範囲内にだけ安全に配置されます。

## Step 1：AIco の資材を配置する

導入先プロジェクトの **Git リポジトリルート** で、作業ツリーに未コミット変更がないことを確認してから次を実行します。

```bash
uv run --refresh https://raw.githubusercontent.com/sasaki819/AIco/latest/installer/install.py
```

※ `latest` の部分をリリースタグ（例：`v0.1.0`）に置き換えて特定のバージョンを導入することもできます。  
※ `--refresh` はローカルキャッシュにより意図しないバージョンが実行されることを防止するための指定です。  
※配置に続けてそのまま対話形式の初期設定まで起動したい場合は、末尾に `--init` を付けて実行することもできます。

* **オフライン環境や `uv` を使わない場合**：AIco リポジトリを手元へ `git clone`（またはリリースアーカイブを展開）し、導入先プロジェクトルートから `python3 /path/to/aico/installer/install.py`（Windows は `py -3 ...`）を実行します。
* **社内ミラーや別リポジトリから導入する場合**：`--source <Git URL>` を指定して実行します。
* **既存の `management/` ディレクトリと衝突する場合**：`--management-root <別名>` で配置先フォルダ名を変更できます。

## Step 2：プロジェクト固有の初期設定を行う（`init`）

配置が完了したら、同じプロジェクトルートで初期設定ウィザードを実行します。

```bash
tools/aico.sh init
```

Windows 環境では `tools\aico.bat init` を使用します。  
画面の案内に従って以下を設定すると、利用ツールのスキル同期・ワーカー定義生成・一覧初期化・診断まで自動で完了します。

1. **統合ブランチ名（`integration_branch`）**：通常は `main` または `develop`（自動検出された既定値のまま Enter でも可）
2. **利用する AI ツール（`tools`）**：使うツールをカンマ区切りで指定（例：`claude,codex`）
3. **アップデート参照先 Git URL（`source_repository`）**：通常は既定値のまま Enter
4. **PR/MR テンプレートパス（`pr_template`・任意）**：既定は空欄です。単一の PR/MR テンプレートを `aico-ticket-pr` で使いたい場合のみ相対パス（例：GitHub は `.github/pull_request_template.md`、GitLab は `.gitlab/merge_request_templates/Default.md`、Azure DevOps は `.azuredevops/pull_request_template.md`）を入力してください。指定先にファイルが無ければ AIco 推奨雛形を配置し、既存ファイルは上書きしません。複数テンプレートを使い分けるプロジェクトや `aico-ticket-pr` を使わない場合は空欄のまま Enter でスキップできます。
5. **`worker_models` 設定**：初回は `N`（空欄のまま）で進めても各ツールの既定モデルで動作します。おすすめ設定を入れたい場合は [おすすめ `worker_models` 設定例](05.worker-models.md) を参照してください。

非対話で設定したい場合は、オプション指定でも実行できます（PR/MR テンプレートを同時設定する場合は `--pr-template <パス>` を追加します）。

```bash
tools/aico.sh init --integration-branch main --tools claude,codex
```

## Step 3：`AGENTS.md` にプロジェクト固有のルールを追記する

プロジェクトルートの `AGENTS.md` には `<!-- AICO:BEGIN -->` 〜 `<!-- AICO:END -->` で囲まれた AIco 管理ブロックが配置されています。  
AIco が迷わず作業できるよう、**マーカーの外側（末尾など）** へプロジェクト固有の情報を追記してください。

```markdown
## プロジェクト固有ルール

* **テスト実行**：`npm test`（または `pytest` など）
* **リンター・整形**：`npm run lint`
* **作業ブランチ命名**：`feature/<チケットID>`
* **レビュー基準**：実装完了後に必ず `aico-review` を実施する
```

※`<!-- AICO:BEGIN -->` 〜 `<!-- AICO:END -->` の内側や `.agents/skills/aico-*`、`management/scripts/` などはアップデート時に更新される AIco 管理領域のため、直接編集しないでください。

### Windows 混在環境向けの任意推奨設定（`.gitattributes`）

AIco の管理記録は UTF-8・LF 改行を規約としています。Windows と macOS / Linux が混在するチームでは、リポジトリルートに `.gitattributes` を置いて改行コードを揃えておくと、チェックアウト時の CRLF 変換による `doctor.py` エラーを未然に防げます（任意設定です）。

```gitattributes
*.md text eol=lf
*.json text eol=lf
*.py text eol=lf
*.sh text eol=lf
*.toml text eol=lf
*.bat text eol=crlf
```

## Step 4：動作確認と初回コミット

設定が終わったら診断コマンドを実行し、`ERROR` が 0 件であることを確認します。

```bash
tools/aico.sh doctor
```

※`worker_models` が未設定のあいだは `WARN` が表示されますが、エラーではないためそのまま使い始められます。

続いて、普段使っている AI ツールでこのプロジェクトを開き、`AGENTS.md` と `aico-*` スキルが認識されることを確認してから初回コミットを行います。  
ここまで完了したら、[チュートリアル（最初の 1 チケットを回してみよう）](02.tutorial.md) に進んで実際のワークフローを体験してみてください。

## AIco のアップデート方法

AIco 本体に新しいバージョンが出たら、統合ブランチ上のクリーンな作業ツリーで次を実行します。

```bash
tools/aico.sh update --check
tools/aico.sh update
```

事前に変更予定ファイルだけ確認したい場合は `--dry-run` を付けて実行してください。
