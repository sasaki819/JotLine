# 設計書（旧 Spec 0007 design.md）

## 概要

旧 `specs/0007-send-cards-to-group/design.md` の設計内容を AIco チケットノートとして移行保存したもの。

> これは本 Item による変更分の設計であり、全体のマスターは docs/architecture/ にある。
> Item 完了時に、この内容を docs/architecture/ へ反映する。

## 変更の概要

カードの右クリックメニューに「Send to group／グループへ移動」を追加する。子メニューには現在の名前付きグループを表示順に並べ、その下に区切り線と「Ungroup／グループ解除」を置く。

カードの移動は、対象をドキュメント順にまとめて取り出し、選択先の末尾へ一括挿入する。カードのグループ解除も共通の移動処理でファイル末尾に配置する。スレッド解散は別の操作に分離し、その場で名前だけを外す既存の動作を維持する。

## 影響範囲

| ファイル | 変更 |

| `src/parser.ts` | 複数カードの一括移動、末尾へのグループ解除、移動を伴わないスレッド解散 |
| `src/store.ts` | 移動・解除・解散の保存処理と失敗時の復元 |
| `src/ui/App.svelte` | 新しいメニューの追加、移動先・対象 ID の受け渡し、選択解除 |

データ形式、カード本文、ドラッグ＆ドロップの処理は変更しない。依存関係の追加と minAppVersion の引き上げも行わない。

## 構成とコンポーネント

### 1. 対象カードとメニュー

- `handleContextMenuCard()` の既存の選択規則を維持する。選択済みカード上の右クリックでは選択全体、未選択カード上ではその1枚を対象にする。
- メニューを開いた時点の対象 ID 配列をコピーして各コールバックに保持する。選択した順序には依存せず、実際のカード順は実行時にモデルから取得する。
- 単一・複数選択の両方で共通の `addCardMoveMenu()` を使い、名前付きグループを `doc.groups` の順に列挙する。候補にはグループ ID と表示名を保持し、同名でも統合しない。現在の所属グループも含める。
- 名前付きグループ候補がある場合は、その末尾に区切り線を置き、最後に Ungroup を追加する。名前付き候補がない場合は不要な先頭の区切り線を出さず Ungroup のみ表示する。対象カードがあれば、既に未分類のカードも末尾へ移動できる。
- 既存の新規グループ化・コピー・削除・グループ解除の項目は維持する。既存のカードのグループ解除も新しい末尾配置処理へ接続する。
- 移動を実行した後は既存の操作と同様に選択を解除する。保存失敗時も選択を解除し、復元によって振り直されたカード ID を選択状態に残さない。メニューを閉じただけでは移動しない。

### 2. サブメニューの互換性

インストール済み `obsidian.d.ts` の公開 `MenuItem` には `setSubmenu()` がない。公開 API の宣言は [Obsidian API の型定義](https://github.com/obsidianmd/obsidian-api/blob/master/obsidian.d.ts) も参照する。実行時に同メソッドを使用する [プラグイン実装例](https://github.com/pan4ratte/obsidian-publish-to-telegram/blob/main/main.ts) はあるが、公開された互換性保証としては扱わない。

- `cardMoveMenu.ts` 内だけで、`MenuItem` に optional な `setSubmenu(): Menu` がある形へ狭く型付けする。実行時に関数であることを確認してから呼び出し、提供される環境ではその子メニューを使用する。
- 提供されない環境では、親項目のクリックで親メニューを閉じ、同じ候補と Ungroup を持つ別の `Menu` を開く。初回の右クリック位置を保持し、公開 API の `showAtMouseEvent()` で表示する。子メニューを選んだ時にだけ移動する。
- メニュー作成失敗時もデータ操作はしない。デスクトップの実サブメニューと未対応環境の子メニュー経路をテストで分けて確認し、モバイルは実画面でも確認する。

### 3. 一括移動の共通処理

`parser.ts` の内部ヘルパーで、名前付きグループへの移動と末尾の未分類への移動を扱う。手順は次のとおり。

1. 入力 ID を Set にして重複を除き、空なら変更しない。現在のドキュメントを先頭から走査し、対象カードの元のオブジェクトを表示順に収集する。ID が1件でも見つからない場合は、操作全体を変更なしとして終了する。
2. 名前付き移動では指定 ID のグループが現在も存在し、名前付きであることを確認する。未分類への解除では、操作前の最後のグループが未分類ならそれを移動先として保持し、名前付きなら新しい未分類グループを末尾に作る計画にする。途中の未分類グループは移動先にしない。
3. 全グループから対象カードだけを除いたカード配列を組み立て、移動先の残存カードの後ろに収集したカードを一度だけ追加する。途中の削除段階ではドキュメントを空にしたり、フォールバックのグループを作ったりしない。
4. 移動によって空になった元グループのうち、名前付きグループを除去する。移動先のグループは保持し、対象を含まない既存グループの名前・ID・順序は維持する。未分類グループは既存の削除規則に合わせて空でも保持する。
5. 最終的なグループ・カードの構成が変わらなければ false を返し、元のモデルを変更しない。変わる場合にだけ構成を反映して true を返す。カード ID と本文を維持する。

新しい末尾グループを作る場合は、途中のグループ削除によって別の未分類グループが末尾に現れても、操作前に決めた移動先を変えない。移動対象が既に移動先の末尾に同じ順で並んでいれば、保存・履歴・成功通知を増やさない。

### 4. カードのグループ解除とスレッド解散

- `ungroupCards()` は共通処理の「末尾の未分類」を使う実装へ変更する。既存のカードの右クリック・選択アクションバーと新サブメニューは、同じ `store.ungroupSelectedCards()` を使用する。
- `dissolveGroupInDoc()` を追加し、指定した名前付きグループの名前を空文字にする。カードの位置・順序・ID は変えない。
- `store.dissolveGroup()` を追加し、`GroupView.svelte` のスレッド解散をこの操作へ接続する。カード移動と解散は明示的に異なる入口にする。

### 5. 保存と履歴

- 名前付きグループへの移動、カードのグループ解除、スレッド解散を、それぞれ1回の `applyChange()` で実行する。複数カードに対して保存を繰り返さない。
- 既存の `save()` により変更前のテキストを履歴へ1件記録し、Undo／Redo と再読み込みで所属・順序を復元できるようにする。
- 書き込み失敗は既存の `writeFile()` で通知し、`applyChange()` が `currentText` からモデルを復元する。成功通知を追加する場合は、保存成功時にだけ表示する。無変更・失敗時には成功通知を出さない。

## インタフェース

| `dissolveGroupInDoc(doc, groupId): boolean` | 指定グループをその場で解散 |

| `JotStore.ungroupSelectedCards(cardIds): Promise<boolean>` | 既存の引数を維持し、末尾配置と失敗時の復元へ切り替え |
| `JotStore.dissolveGroup(groupId): Promise<boolean>` | 解散を保存 |
| `addCardMoveMenu(menu, groups, cardIds, callbacks, event)` | メニュー構築を UI 本体から切り出し、対応差と候補を共通化 |

新しい文言キーは英語・日本語の両辞書に追加する。親項目は `Send to group`／`グループへ移動`、子の解除項目は `Ungroup`／`グループ解除` とする。グループ名は HTML として解釈せずメニューのタイトル文字列として渡す。

## データモデル

`JotCard`、`JotGroup`、`JotDocument` と Markdown マーカーの変更はない。操作中の移動先・対象 ID は一時的に保持する。新しいグループ ID は末尾の未分類グループが必要な場合だけ生成する。

## エラー処理

- メニュー表示後に対象カードや移動先が外部更新などで消えていた場合は、実行時の ID 検証で変更なしとして終了する。名前が同じ別グループへ振り替えたり、一部のカードだけを移動したりしない。
- 空の選択・既に同じ末尾配置の場合は変更しない。
- 保存失敗は既存の通知と復元処理を使う。復元で ID が変わり得るため、実行元 UI は終了時に選択状態を解除する。
- 今回の操作のために既存の移動・削除をカード枚数分呼び出す方式は使わず、検証後に一括反映・保存する。

## テスト方針

| 層 | 主な確認 | 対応する受入基準 |
|---|---|---|
| parser | 未分類から名前付きへ、別グループへ、現在の所属グループ末尾へ、同名グループの ID 指定 | AC2〜AC4 |
| parser | 選択順を逆にした複数移動、複数グループにまたがる選択、移動先の内外の混在、対象外の順序・本文・ID の維持 | AC3・AC6 |
| parser | 末尾が未分類なら再利用、名前付きなら新規末尾、途中にだけ未分類がある場合、元グループ全カードの解除、既に未分類のカードも含む移動 | AC6・AC10・AC11 |
| parser | 無効なグループ／カード ID、重複 ID 入力、空選択、末尾配置が変わらない場合、移動元が空になる場合 | AC3・AC8 |
| store | 保存回数、再読み込み、単一／複数移動と解除の Undo・Redo、保存失敗時の復元、無変更時に履歴を増やさないこと | AC7・AC8 |
| menu | 名前付き候補の順序・同名候補・現在の所属先、区切り線と最後の Ungroup、日本語／英語、候補がない場合、閉じるだけでは呼び出さないこと | AC1・AC2・AC8・AC9 |
| menu／UI | 選択済み・未選択カードを右クリックした場合の対象、サブメニュー対応／未対応経路、既存のグループ解除も同じ保存操作を呼ぶこと | AC5・AC11 |
| スレッド解散 | 中間にあるスレッドを解散しても全カードがその位置に残ること、保存と Undo・Redo | AC11 |

- 既存の parser のグループ解除テストは、新しい末尾配置の期待値へ更新する。その場での解散は独立したテストとして残し、旧来のテストを単に削除しない。
- メニューは Obsidian の Menu／MenuItem のテスト用実装で候補・区切り・コールバックを検証する。既存の jsdom・esbuild-svelte のテスト方式も利用し、実際の UI と選択処理を確認する。
- 機械検証は `npm run build`、`npm test`、`npx tsc --noEmit`、`bash tools/ai-standard/check-docs.sh`。
- Obsidian のデスクトップ実画面ではサブメニューの開閉・クリック・区切り・表示順、複数選択、解除後の末尾配置、再読み込み、Undo／Redo を確認する。モバイルでは既存のカードメニューを開く操作から、候補と Ungroup の選択が利用できることを確認する。自動テストは実画面でのメニュー互換性の確認を代替しない。
- minAppVersion 1.1.0 を維持するため、その環境での未対応経路と利用中の対応環境を分けて確認する。実環境を用意できない項目は未確認として記録する。

## 検討した代替案

- 既存の1枚移動を対象カードごとに実行する：位置補正と順序維持が複雑になり、保存・履歴も複数になるため、一括操作を採用する。
- 本文をコピーして元カードを削除する：カード ID が変わり、重複・消失の扱いも複雑になるため、元のカードオブジェクトを移す。
- グループ名で移動先を指定する：同名グループを区別できないため、ID を使用する。
- 既存の `ungroupCards()` を全カードの解散にも使い続ける：カードの解除は末尾移動、スレッド解散はその場での名前解除という承認済み要件を満たすため、入口を分離する。
- 公開型にないサブメニュー API を無条件に呼ぶ：未対応環境でメニュー全体が動かなくなるため、実行時の判定と公開 API による子メニュー表示を組み合わせる。
