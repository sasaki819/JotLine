# 設計書（旧 Spec 0006 design.md）

## 概要

旧 `specs/0006-append-main-input-card-at-end/design.md` の設計内容を AIco チケットノートとして移行保存したもの。

> これは本 Item による変更分の設計であり、全体のマスターは docs/architecture/ にある。
> Item 完了時に、この内容を docs/architecture/ へ反映する。

## 変更の概要

メイン入力欄からの追加先を、先頭の未分類グループからドキュメント末尾に切り替える。末尾のグループが未分類ならその末尾へ追加し、名前付きなら末尾に新しい未分類グループを作って追加する。既存のグループとカードは移動しない。

## 影響範囲

- `src/store.ts` の `JotStore.addCard(content)`。引数 `targetGroupId` を指定した呼び出しの追加先は現状どおりとする。
- `src/store.test.ts` の追加位置と保存・再読み込みの回帰テスト。
- Item 完了時に `docs/architecture/03.UI-UX-Specification.md` のメイン入力バーの説明を更新する。データ形式のマーカー構文自体は変えない。

## 構成とコンポーネント

1. `InputBar.svelte` は引き続き `store.addCard(text)` を呼ぶ。UI から追加先を指定する処理は増やさない。
2. `JotStore.addCard` は `targetGroupId` が省略された場合、`current.groups.at(-1)` を調べる。末尾が未分類ならそのグループへカードを追加する。末尾が名前付き、またはグループが無い場合は、`name: ""` のグループを `current.groups` の末尾へ作ってからカードを追加する。
3. `targetGroupId` が指定された場合は、既存の指定グループ検索と、見つからない場合の処理を維持する。
4. 既存の `save()` がグループ配列の順に Markdown をシリアライズする。名前付きグループの後に新設した未分類グループは、`<!-- group -->` と `<!-- card -->` を伴ってファイル末尾に保存される。`parseJotDocument` は同じ順序で再読み込みする。パーサーとシリアライザーに変更は不要。

## インタフェース

- `JotStore.addCard(content: string, targetGroupId?: string)` のシグネチャは変えない。
- メイン入力欄の Enter と送信ボタンは、どちらも従来どおり引数なしの追加先指定で呼ぶ。
- Markdown マーカーの構文は既存の `<!-- group -->` / `<!-- card -->` を使う。

## データモデル

`JotDocument.groups` の末尾に `name: ""` の未分類グループが来ることを許す。未分類グループは既存のパーサーでも複数保持できる。例えば先頭の未分類カード、名前付きグループ、新しい未分類カードの順序は、次のように保存する。

```markdown
<!-- group -->
<!-- card -->
既存の未分類カード

<!-- group: topic -->
<!-- card -->
既存のグループ内カード

<!-- group -->
<!-- card -->
新しい未分類カード
```

続けて送信すると、最後の未分類グループに新しい `<!-- card -->` を増やす。先頭の未分類グループにカードを移動したり、名前付きグループへ新規カードを混ぜたりしない。

## エラー処理

- 空白だけの入力は、既存の `addCard` と同じく保存せずに終了する。
- 保存失敗時の通知と履歴の扱いは既存の `save()` に従う。新しい保存経路は設けない。

## テスト方針

- `JotStore` の実際の `addCard` と偽 Vault を使い、先頭に未分類グループ、その後ろに名前付きグループがある場合に、保存テキストの末尾が新しい未分類グループとカードになり、既存カードの内容・所属・順序が変わらないことを確認する。
- 名前付きグループだけの場合、未分類グループだけの場合、空ファイルの場合、連続送信の場合も確認する。連続送信では最後の未分類グループを再利用し、入力順に並ぶことを確認する。
- 保存テキストを再読み込みし、表示用のグループ配列でも新規カードが末尾にあり、名前付きグループに属さないことを確認する。
- `targetGroupId` を指定した追加が既存の対象グループに入ることを回帰確認する。
- `npm test`、`npx tsc --noEmit`、`npm run build` を実行する。

## 検討した代替案

- **先頭の未分類グループを末尾へ移動する**: 既存カードの順序が変わり、受入基準 AC4 を満たさないため採用しない。
- **最後の名前付きグループへ追加する**: 新規カードがそのグループに属してしまい、受入基準 AC2 を満たさないため採用しない。
- **新規カードのたびに未分類グループを作る**: 連続した未分類カードに不要なグループ宣言が増えるため採用しない。末尾が未分類のときは再利用する。
