# 0001. アンドゥ／リドゥの操作履歴をファイル内容のテキストスナップショットとして持つ

## Context

- JotLine ビューで行った操作（カードの追加・編集・削除・分割・統合・移動、グループ操作など14種類）を、アンドゥ／リドゥできるようにする必要があった（Item 0003）。削除系の操作は確認なしで即時実行されるため、誤操作を戻す手段がなかった。
- JotLine は、操作のたびにメモリ上の `JotDocument` をシリアライズし、ファイル全体を上書き保存する。カード・グループの ID はパースのたびに採番され、ファイルには保存されない。
- 同じファイルは、標準エディタ・同期・Git などで外部から変更されることがある。要件として、外部変更も1件の履歴としてアンドゥできるようにすることになった。
- JotLine で開く対象は、マーカーを含まない通常のノートのこともある。この場合、最初の操作でマーカー付きの形に書き換わるため、アンドゥでは元のテキストに正確に戻る必要がある。
- Item 0004（D&D によるカードとノート間の移動）では、JotLine 側でのカード削除を、このアンドゥで戻せることを前提にしている。

検討した方式:

1. 操作ごとの逆操作（コマンドパターン）
2. `JotDocument` オブジェクト（ID 付き）のスナップショット
3. テキストの差分（diff）の保存
4. ファイル内容（テキスト全体）のスナップショット

## Decision

- 操作履歴の1件を、**変更直前のファイル内容（Markdown テキスト全体）のスナップショット** とする。
- 履歴は `JotStore` が保存処理と外部変更の取り込みの中で積む。
  - JotLine 上の操作：保存処理（`save()`）で、書き込みに成功したら変更前の内容を積む（1回の操作 = 1件）。内容が変わらない場合は書き込みも記録もしない。
  - 外部変更：`modify` イベントで読み直した内容が直前の内容と異なれば、変更前の内容を積む（検知1回 = 1件）。
- アンドゥ／リドゥは、戻り先のテキストをファイルへ書き込み、既存のパーサーで読み直して表示を置き換える。
- 履歴はメモリ上のみで保持し（上限100件）、`JotStore` のインスタンスとともに破棄する（ビューを閉じたとき、別ファイルに切り替えたとき）。
- スタック操作は Obsidian に依存しない `UndoHistory`（`src/history.ts`）に分ける。

方式1〜3を採らなかった理由:

- 方式1（逆操作）：14種類すべてに逆操作の実装とテストが必要で、漏れや不整合が起きやすい。外部変更を表せない。
- 方式2（`JotDocument` のスナップショット）：ID を保てる利点はあるが、パース・シリアライズを経るため、外部変更前の内容やマーカーのない元のテキストを正確に表せない。
- 方式3（差分）：実装が複雑になる割に、想定するファイル規模（数十KB程度）と上限100件では、メモリの節約が必要にならない。

## Consequences

良い面:

- 外部変更前の状態や、マーカーのない通常のノートの元のテキストに、正確に戻せる。
- 保存処理を通る操作は、操作ごとの追加実装なしで自動的にアンドゥの対象になる（今後追加する操作も同様）。
- 戻す処理は「書き込み → 既存のパーサーで読み直し」だけで、データフォーマットにも既存の操作にも手を入れずに済む。
- 履歴のロジックが小さく、Obsidian に依存しない部分を単体テストできる。

悪い面・制約:

- アンドゥ／リドゥのたびにパースし直すため、カード・グループの ID が振り直される。カードの選択は保てず、アンドゥ／リドゥ後は選択を解除する。カードの編集中・返信入力中・スレッド名の編集中の未保存テキストも破棄される（外部変更の読み直し時と同じ）。
- 1件がファイル全体のテキストのため、ファイルが非常に大きい場合はメモリ使用量が増える（上限100件 × ファイルサイズ程度）。大きなファイルを扱う必要が出たら、差分保存などへの変更を検討する。
- 外部変更も履歴に入るため、JotLine のアンドゥで外部での変更を取り消せてしまう（要件として受け入れた動作）。
- 自己保存の直後300ms以内に起きた外部変更は検知されず、履歴にも入らない（既存の制約）。その後にアンドゥすると、その外部変更は上書きされる。

今後必要になること:

- 新しい操作を追加するときは、保存処理（`save()`）を通すことでアンドゥの対象になる。保存処理を通さずにファイルを書き換える処理を追加する場合は、履歴の扱いを別途検討する。
- Item 0004 で JotLine 側のカードを削除する処理も、保存処理を通すことでアンドゥの対象にする。
