# design: 0010 グループ名の変更をフォーカスアウト時に確定する

> これは本 Item による変更分の設計であり、全体の正本は docs/architecture/ にある。
> Item 完了時に、この内容を docs/architecture/ へ反映する。

## 変更の概要

グループ名編集欄の確定・キャンセルボタンを削除する。入力欄の Enter と blur を共通の確定処理に接続し、Esc はキャンセル処理に接続する。

確定またはキャンセルの開始時に編集状態を同期的に終了させ、その後の blur が保存を再実行しないようにする。

## 影響範囲

- `src/ui/GroupView.svelte`：編集欄のイベント、確定・キャンセル処理、ボタンの表示を変更する。
- `docs/architecture/03.UI-UX-Specification.md`：グループ名編集の確定・キャンセル操作を反映する。
- `JotStore.renameGroup()` と Markdown の保存形式は既存のものを利用する。

## 構成とコンポーネント

### 編集の開始

既存の編集開始操作で `editingName` に現在の名前を設定し、`isRenaming` を true にする。入力欄の Svelte action で DOM への挿入時に `focus()`、続けて `select()` を呼ぶ。ダブルクリックと編集ボタンのどちらから開始しても、追加クリックなしでキー操作と blur を受け取れ、既存の名前全体を入力で置き換えられるようにする。

### 確定

`saveRename()` の処理順序を次のようにする。

1. `isRenaming` が false なら何もしない。
2. `editingName.trim()` とグループ ID をローカル変数に保持する。
3. 非同期処理を待つ前に `isRenaming` を false にして編集状態を終了する。
4. 名前が空、または現在の名前と同じなら保存せず終了する。
5. それ以外は既存の `store.renameGroup()` を1回呼び出す。

入力欄の blur と Enter の両方からこの処理を呼び出す。入力欄の削除によって blur が発生した場合や、保存完了前に確定イベントが重なった場合も、手順1の判定で重複を防ぐ。

### キャンセル

`cancelRename()` は `isRenaming` を false にし、`editingName` を現在のグループ名に戻す。ストアへの変更は行わない。編集欄の消失に伴う blur は、確定処理の編集状態判定で無視する。

### 入力欄のイベント

- `blur`：確定処理を呼び出す。
- `keydown` の Enter：確定処理を呼び出す。
- `keydown` の Escape：キャンセル処理を呼び出す。
- 日本語などの IME 変換中のキー操作は、グループ名の確定・キャンセルとして扱わない。

確定・キャンセルボタンの要素を削除し、入力欄を残す。

## インタフェース

公開インタフェースの変更はない。既存の `store.renameGroup(groupId: string, newName: string): Promise<boolean>` を利用する。編集状態の管理と重複防止は `GroupView.svelte` 内で完結させる。

## データモデル

変更なし。既存の `isRenaming` と `editingName` を利用する。保存待ち状態や新たな永続データは追加しない。

## エラー処理

空白のみの名前と変更のない名前は、既存どおり保存せずに編集を終了する。ファイルへの書き込み失敗は既存のストアのエラー処理・通知に委ねる。保存失敗時の再編集や再試行の仕組みは変更しない。

## テスト方針

- `npm run build`、`npm test`、`npx tsc --noEmit` を実行し、既存のビルド・データ操作・保存処理に回帰がないことを確認する。
- `scripts/group-rename.test.mjs` で、production と同じ esbuild-svelte を使ってコンポーネントをコンパイルし、jsdom 上で実際の JotStore と接続する。編集開始直後のフォーカス、Enter／blur の保存、Esc のキャンセル、保存待ちでの重複防止、IME を検証する。テスト側では入力欄を手動でフォーカスしない。
- Obsidian 上でも次の手動確認を行い、結果を progress に記録する。jsdom の検証は Obsidian 実画面とモバイルの確認を代替しない。

| 操作 | 期待する結果 | 対応する受入基準 |
|---|---|---|
| 名前を変更し、編集欄の外をクリックする／Tab で移動する | 編集終了後に新しい名前が表示され、再読み込み後も維持される | AC1 |
| 名前を変更し Enter を押す | ボタンがない状態で確定・保存される | AC2 |
| Enter 後にフォーカスが外れる操作、保存完了前の Enter の連打 | 保存・成功通知が重複しない。Undo 1回で元の名前に戻る | AC3 |
| 名前を変更し Esc を押し、その後別の場所をクリックする | 元の名前に戻り、保存・成功通知が発生しない | AC4 |
| 前後に空白を含む名前／空白のみ／変更のない名前で確定する | 前後の空白は除去され、空白のみ・変更なしでは保存・成功通知が発生しない | AC5 |
| IME で文字を変換中に Enter／Esc を押す | 変換操作のみが行われ、編集が継続する | 入力イベントの整合 |

- デスクトップでは Enter・Esc・Tab・クリックを確認し、モバイルでは編集欄外へのタップによる確定を確認する。
- 文書更新後に `bash tools/ai-standard/check-docs.sh` を実行する。

## 検討した代替案

- 入力欄の blur から、既存の確定処理をそのまま呼ぶ：非同期保存の完了まで編集状態が続くため、Enter と blur による重複処理を防ぎにくい。
- 確定・キャンセルボタンを残し、フォーカスの移動先によって保存を制御する：ユーザーの変更指示に従い、ボタンを削除して入力欄のイベントに統一する。
- タイマーで blur の処理を遅らせる：ボタン間のフォーカス移動を考慮する必要がなく、編集状態の同期的な終了で対応できるため採用しない。
