### 作業ログ

### 判断とその理由

- **ショートカット**: ビュー内のキー処理（Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z、Ctrl+Y）に加え、既定ホットキーなしのコマンドを登録する（ユーザーの選択）。既定ホットキーを設定しないのは、Obsidian のエディタの Mod+Z との競合を避けるため。
- **ボタン**: ヘッダー右側の既存ボタンの並びに置く（ユーザーの選択）。
- **履歴の保持**: ビュー（ファイル）ごと、上限100件、ビューを閉じるか別ファイルに切り替えたら破棄（ユーザーの選択）。
- **外部変更**: 検知した外部変更も1件の履歴として積む（ユーザーの選択）。外部変更を検知した時点でリドゥ履歴は破棄する。連続する外部変更を1件にまとめる処理と、既存の「自己保存の直後300ms以内の外部変更は検知されない」制約の解消は、スコープ外とした。
- **選択状態**: アンドゥ／リドゥの後は選択をすべて解除する（ユーザーの選択）。既存の「外部変更で読み直した後に、どのカードにも対応しない古い選択と選択バーが残る」問題も、同じ仕組みで解消するためこの Spec に含めた（ユーザーの選択）。
- **メイン入力欄での Ctrl/Cmd+Z**: 入力欄が空のときだけ JotLine のアンドゥとする。メモ送信直後もフォーカスが入力欄に残るため、送信をそのまま取り消せるようにした。
- **未保存の入力の扱い**: カードの編集中・返信入力中・スレッド名の編集中のテキストは、アンドゥ／リドゥや外部変更の読み直しで破棄される（カードとスレッドが ID ごとに作り直されるため。現状の外部変更時と同じ）。メイン入力欄のテキストは残る。
- **実装方式**: 履歴の1件を「操作直前のファイル内容（テキスト全体）」とする。外部変更前の状態や、マーカーのない通常のノートの元のテキストを正確に戻せ、カード ID を履歴の前後で引き継ぐ必要もないため。代替案（逆操作、`JotDocument` のスナップショット、差分保存）は design.md の「検討した代替案」に記載。
- **コマンド名**: 既存のコマンドと同じく i18n 辞書から取る。日本語環境では「JotLine: 元に戻す」「JotLine: やり直す」になる（ユーザー確認済み。requirements の AC9 に注記した）。
