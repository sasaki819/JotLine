# requirements: 0003 JotLine ビューにアンドゥ／リドゥ機能を追加する（ショートカット＋ボタン）

## 背景

- JotLine ビュー（サイドペイン・メインエリアとも）で行った操作は取り消せない。`JotStore` は操作履歴を持たず、各操作は即座にファイル全体を上書き保存する。
- Obsidian 標準の Ctrl/Cmd+Z は Markdown エディタ向けの機能のため、JotLine ビューでは効かない。
- カード削除・一括削除・スレッド削除は確認ダイアログなしで即時実行されるため、誤操作がそのままデータ消失につながる。
- Item 0004（D&D によるカードとノート間の移動）では JotLine 側のカード削除を伴うため、それを安全に戻せる仕組みが前提として必要になる。

## 目的

JotLine ビューで行った操作と、外部でのファイル変更を、取り消し（アンドゥ）・やり直し（リドゥ）できるようにし、誤操作によるデータ消失を防ぐ。

## スコープ

- **履歴の対象**: 次の「1回の操作」をそれぞれ1件の履歴とする。
  - JotLine ビューで行った、ファイル内容を変更する操作：カードの追加・編集・削除・分割・統合・上下移動・D&D 並び替え、返信、グループ化・グループ化解除・スレッドのリネーム・解散・削除、一括削除（右クリックメニューからの操作を含む）
  - 外部（標準エディタ、同期、Git、他アプリなど）によるファイル変更のうち、JotLine が検知して再読み込みしたもの（検知1回につき1件）
- **アンドゥ／リドゥの動作**:
  - アンドゥで直前の履歴の1件前の状態へ、リドゥでアンドゥした状態へ戻す。結果はファイルに保存する。
  - 新しい操作（または外部変更の検知）があった時点で、リドゥ履歴は破棄する。
- **履歴の保持**:
  - 表示中のファイルごと（JotLine ビューごと）にメモリ上で保持する。ファイルには保存しない。
  - 上限は100件。超えた場合は古いものから破棄する。
  - ビューを閉じたとき、または同じビューで別のファイルに切り替えたときに破棄する。
- **キーボードショートカット**（JotLine ビューにフォーカスがあるとき）:
  - アンドゥ：Ctrl/Cmd+Z
  - リドゥ：Ctrl/Cmd+Shift+Z、Ctrl+Y
  - 文字入力欄との関係：
    - カード編集欄・返信欄・スレッド名編集欄にフォーカスがある間は、ショートカットを横取りせず、入力欄の標準のアンドゥ／リドゥに任せる。
    - メイン入力欄にフォーカスがある間は、**入力欄が空のときだけ** JotLine のアンドゥ／リドゥとして扱う（メモ送信直後に、そのまま送信の取り消しができるようにするため）。入力中の文字がある間は入力欄の標準動作に任せる。
- **コマンド**: 「JotLine: Undo」「JotLine: Redo」をコマンドとして登録する。既定のホットキーは設定せず、コマンドパレットや、利用者が割り当てたホットキーから実行できる。対象はアクティブな JotLine ビュー。
- **カードの選択状態**:
  - アンドゥ／リドゥを実行したら、カードの選択をすべて解除する。
  - 外部変更を検知してファイルを再読み込みしたときも、カードの選択をすべて解除する（現状は再読み込み後も、どのカードにも対応しない古い選択が残り、選択バーが表示されたままになる。この既存の問題もこの Item で解消する）。
- **ボタン**: ヘッダー右側（既存の「📋 全件コピー」「📝 エディタ」ボタンの並び）に、アイコンのみのアンドゥ／リドゥボタンを置く。実行できない（履歴がない）ときは無効表示にする。ツールチップは i18n 辞書（en / ja）で提供する。

## スコープ外

- 文字入力欄（カード編集欄など）の中での入力途中のテキストのアンドゥ（ブラウザ標準の動作のまま）。
- カードの選択状態、スレッドの開閉状態、スクロール位置など、ファイル内容に含まれない表示状態のアンドゥ（選択状態はアンドゥ／リドゥ時に解除する。スコープを参照）。
- カードのインライン編集中・カードへの返信入力中・スレッド名の編集中の、未保存のテキストの保持。アンドゥ／リドゥや外部変更による再読み込みの際は、現状の外部変更時と同じく破棄される。なお、メイン入力欄で入力中のテキストは破棄されず、そのまま残る。
- 履歴の永続化（Obsidian の再起動やビューの開き直しをまたいだアンドゥ）。
- 削除操作への確認ダイアログの追加。
- 既存の制約である「自己保存の直後300ms以内に発生した外部変更は検知されない」の解消。この間の外部変更は履歴にも入らない。解消が必要なら別の Item とする。
- 外部変更を検知した際に、連続する変更を1件にまとめる処理（検知1回につき1件のまま扱う）。

## 受入基準

- [ ] AC1: スコープに挙げた JotLine の各操作について、操作後にアンドゥすると、ファイル内容が操作前と同一の内容に戻る（単体テストで、各操作の前後のシリアライズ結果を比較して確認する）。
- [ ] AC2: アンドゥ後にリドゥすると、ファイル内容がアンドゥ前と同一に戻る。アンドゥ後に新しい操作を行うと、リドゥできなくなる（単体テストで確認）。
- [ ] AC3: 外部でファイルが変更されて JotLine が再読み込みした後にアンドゥすると、ファイル内容が外部変更前の内容と同一に戻り、リドゥで外部変更後の内容に戻る。外部変更の検知により、それまでのリドゥ履歴は破棄される（単体テストで確認）。
- [ ] AC4: 履歴が100件を超えると、最も古い履歴から破棄され、101件目以降はアンドゥできない（単体テストで確認）。
- [ ] AC5: アンドゥ／リドゥの結果がファイルに保存され、同じファイルを開いている標準エディタの表示にも反映される（Obsidian 上で手動確認）。
- [ ] AC6: JotLine ビューにフォーカスがあるとき、Ctrl/Cmd+Z でアンドゥ、Ctrl/Cmd+Shift+Z と Ctrl+Y でリドゥできる（Obsidian 上で手動確認）。
- [ ] AC7: カード編集欄・返信欄・スレッド名編集欄、および文字が入力されているメイン入力欄では、Ctrl/Cmd+Z が入力欄の標準のアンドゥとして働き、JotLine のアンドゥは実行されない。メイン入力欄が空のときは JotLine のアンドゥが実行される（Obsidian 上で手動確認）。
- [ ] AC8: ヘッダーにアンドゥ／リドゥボタンがあり、クリックで実行できる。履歴がないときは無効表示になる。ツールチップが英語・日本語の両方で表示される（Obsidian 上で手動確認、i18n 辞書のキーの存在は型検査で確認）。
- [ ] AC9: コマンドパレットに「JotLine: Undo」「JotLine: Redo」（日本語環境では「JotLine: 元に戻す」「JotLine: やり直す」）があり、アクティブな JotLine ビューに対して実行できる。既定のホットキーは設定されていない（Obsidian 上で手動確認）。
- [ ] AC10: ビューを閉じて開き直したとき、または別のファイルに切り替えたとき、履歴は空になっている（Obsidian 上で手動確認）。
- [ ] AC11: 複数のカードを選択した状態でアンドゥ／リドゥすると、選択がすべて解除され、選択バーが消える。複数のカードを選択した状態で標準エディタからファイルを変更すると、再読み込み後に選択がすべて解除され、選択バーが消える（Obsidian 上で手動確認）。
- [ ] AC12: 既存の操作の挙動とデータフォーマットが変わらない。`npm run build`、`npm test`、`npx tsc --noEmit` がすべて成功する。
