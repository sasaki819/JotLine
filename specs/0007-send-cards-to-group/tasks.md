カード移動と保存の実装、メニューへの接続、Obsidian 実画面での受入確認の順に進める。
最後にマスタードキュメントへ反映し、ADR の要否を判断する。

- [x] 1. カードの一括移動・グループ解除と保存を実装する
  - **完了条件**　名前付きグループの末尾への移動と、ファイル末尾の未分類グループへの解除を実装する。対象カードを表示順に移し、本文と ID を保持する。
    移動先が同じ場合や末尾の未分類グループを新設する場合の結果を検証する。
    無効な ID や無変更の場合は保存せず、変更時は1回の保存と履歴記録で処理する。再読み込み、Undo／Redo、書き込み失敗時の復元をテストする。
    スレッドヘッダーの解散を専用処理へ接続し、カードの位置を保つことを確認する。
  - **検証コマンド**　`npm run build`、`npm test`、`npx tsc --noEmit`、`bash tools/ai-standard/check-docs.sh`
- [ ] 2. 右クリックメニューに「グループへ移動」を追加する (after: 1)
  - **完了条件**　既存の右クリック選択規則を使い、単一・複数カードの両方を移動できるようにする。
    日本語・英語の表示、名前付き候補の表示順、同名候補の区別、現在の所属先、区切り線と「グループ解除」をテストする。
    サブメニュー対応環境とクリックで子メニューを開く環境の両経路をテストする。
    メニューを閉じただけでは移動せず、新旧のカード解除操作が同じ末尾配置処理を使うことを確認する。
  - **検証コマンド**　`npm run build`、`npm test`、`npx tsc --noEmit`、`bash tools/ai-standard/check-docs.sh`
- [ ] 3. Obsidian 実画面で受入基準を確認する (after: 2)
  - **完了条件**　design のテスト方針に沿って AC1〜AC11 の確認結果を照合する。実画面ではメニューの開閉と候補選択、複数カードの順序、解除後の末尾配置、再読み込み、Undo／Redo、スレッド解散を確認する。
    デスクトップ・モバイルの確認結果と Obsidian のバージョンを progress に記録する。サブメニュー対応環境と最小対応バージョンでの経路を確認し、実環境を用意できない項目は未確認として記録する。
  - **検証コマンド**　`bash tools/ai-standard/check-docs.sh`（上記の手動確認と併せて実施する）
- [ ] マスタードキュメント（docs/architecture/）へ design の内容を反映 (after: 3)
  - **完了条件**　`docs/architecture/03.UI-UX-Specification.md` に、右クリックメニューの候補と操作、カード解除時の末尾配置、スレッド解散の動作、履歴への反映を記載する。
  - **検証コマンド**　`bash tools/ai-standard/check-docs.sh`
- [ ] ADR の要否判断（必要なら作成） (after: 3)
  - **完了条件**　ADR の要否と理由を progress に記録する。必要な場合は `templates/adr.md` を使って `docs/adr/` に作成する。
  - **検証コマンド**　`bash tools/ai-standard/check-docs.sh`
