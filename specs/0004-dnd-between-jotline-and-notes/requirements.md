# requirements: 0004 D&D によるカードとノート間の移動機能を追加する

## 背景

- JotLine で整理したカードやスレッドを通常のノートへ移すには、Markdown としてコピーしてノートに貼り付け、元のカードを削除する、という手順を踏む必要がある。逆に、ノートの一部をカードにするには、コピーして入力欄に貼り付け、元のノートから削除する必要がある。
- JotLine のカードのドラッグ＆ドロップは、同じビュー内での並び替え（カード1枚）にしか使えない。
- Item 0003 でアンドゥ／リドゥが入り、JotLine 側でカードを削除しても戻せるようになった（ADR 0001）。
- 2026-10-14 に技術的な実現性を評価済み（コードと API 定義の確認のみ。実機での試作は未実施。内容は Item 0004 のメモを参照）。

## 目的

JotLine ビューと Markdown ノート（Obsidian の標準エディタ）の間、および別のファイルを開いている JotLine ビュー同士の間で、ドラッグ＆ドロップによってカードやテキストを移動・コピーできるようにし、収集したメモを整理・活用する手間を減らす。

## スコープ

### ドラッグの元（ドラッグできるもの）

- **JotLine のカード**
  - カード1枚。
  - 複数選択したカード：選択中のカードのうち1枚をドラッグすると、選択中のすべてのカードをドキュメント上の並び順でまとめてドラッグする。
- **JotLine のスレッド**：スレッドヘッダーをドラッグすると、スレッド全体（スレッド名と所属カード）をドラッグする。
- **エディタで選択したテキスト**：標準エディタ（ソースモード、ライブプレビュー）で範囲選択したテキストを、Markdown のソースのままドラッグする。複数の範囲を選択している場合は、エディタが扱うメインの選択範囲だけが対象。

### ドロップ先と結果

| ドラッグの元 → ドロップ先 | 結果 |
|---|---|
| JotLine のカード・スレッド → エディタ（別ファイル） | ドロップ位置に、マーカーを含まない Markdown として挿入する。内容は既存の Markdown コピーと同じ（カード本文を空行区切りで連結。スレッド名は含めない） |
| JotLine のカード → 別ファイルの JotLine ビュー | ドロップ位置（カードの上ならそのカードの位置、グループの余白ならそのグループの末尾）に、元と同じ枚数・同じ本文のカードとして追加する |
| JotLine のスレッド → 別ファイルの JotLine ビュー | 同じスレッド名・同じカードのスレッドとして、ドロップしたグループの直後に追加する |
| エディタの選択テキスト → JotLine ビュー（別ファイル） | 選択範囲全体を1枚のカードとして、ドロップ位置に追加する |
| JotLine のカード・スレッド、エディタの選択テキスト → JotLine のメイン入力欄 | 入力欄のカーソル位置にテキストとして挿入する（カード・スレッドは既存の Markdown コピーと同じ内容）。JotLine のカード・スレッドは **常にコピー**（元は削除しない）。エディタの選択テキストは、ブラウザの標準動作により、ほかのドロップと同じく既定は移動（元のノートから削除）、修飾キーでコピー |

### 移動とコピー

- **既定は移動**：ドロップ先に追加したあと、ドラッグの元を削除する。
  - JotLine のカード・スレッドが元の場合：元の JotLine ビューからカード（スレッドの場合はスレッドごと）を削除する。
  - エディタの選択テキストが元の場合：元のノートから選択範囲を削除する。
- **修飾キーでコピー**：ドロップの時点で Ctrl（Windows / Linux）または Option（macOS）を押していれば、コピー（元を残す）にする。
- メイン入力欄へのドロップは、JotLine のカード・スレッドの場合は修飾キーに関係なく常にコピー。エディタの選択テキストの場合は、ブラウザ（編集可能な領域からのドラッグ）の標準動作により、既定は移動、修飾キーでコピーとなる（JotLine は独自の処理を行わない）。
- 移動は「ドロップ先への追加に成功してから、元を削除する」順で行う。追加に失敗した場合は元を削除しない。元の削除に失敗した場合は、その旨を通知する（内容が重複して残ることはあっても、失われない）。
- 移動で削除した側も、それぞれの側のアンドゥで戻せる。
  - JotLine 側の追加・削除：JotLine のアンドゥ（Item 0003）。1回のドロップで変化した各 JotLine ビューで、それぞれ1件の履歴になる。
  - エディタ側の挿入・削除：エディタのアンドゥ（Ctrl/Cmd+Z）。
  - 移動1回を、両側まとめて1回のアンドゥで戻すことはできない（それぞれの側でアンドゥする）。

### 同じファイルどうしのドロップ

- ドラッグの元とドロップ先が **同じファイル** の場合は、ドロップできないようにする（移動もコピーも行わない）。対象は次のとおり。
  - JotLine ビューと、同じファイルを開いている標準エディタの間（どちらの向きも）。
  - 同じファイルを開いている別々の JotLine ビューの間。
- ドロップしようとしたときは、同じファイルにはドロップできない旨を通知する。
- 例外：
  - 同じ JotLine ビューの中での、既存のカード並び替え（ドラッグしたカード1枚の移動）は、これまでどおり動作する。
  - メイン入力欄へのドロップは、同じファイル由来のものでも許可する（入力欄へのテキストの挿入だけで、ファイルを書き換えないため、保存の衝突が起きない）。

### 既存機能との関係

- 同じ JotLine ビューの中でのカード並び替え（ドラッグしたカード1枚の移動）は、これまでどおり動作する。
- 入力バーへの画像ファイルのドロップは、これまでどおり動作する。
- 対象はデスクトップ版のみ。

## スコープ外

- 同じ JotLine ビューの中で、複数選択したカードやスレッドをまとめてドラッグして並べ替えること（ビュー内の並び替えは、ドラッグしたカード1枚の移動のまま）。
- 移動1回を、両側まとめて1回のアンドゥで戻すこと。
- 読み取りビュー（プレビュー）からのドラッグ（表示用のテキストになり Markdown の書式が失われるため）。
- エディタの選択テキストを、空行などで複数のカードに分けてドロップすること（1枚のカードにする。分けたい場合は既存の分割機能を使う）。
- モバイル版（タッチ操作では HTML5 のドラッグ＆ドロップが動作しないため）。
- ポップアウトウィンドウ（別ウィンドウに切り離したペイン）との間のドラッグ＆ドロップ（動作は保証しない）。
- ファイルエクスプローラーや Canvas など、エディタと JotLine ビュー以外へのドロップ。
- ドラッグ中の見た目の作り込み（複数カードをまとめた専用のドラッグ画像など）。ドロップ位置の表示は、既存のグループのハイライトとエディタ標準の表示を使う。

## 受入基準

- [ ] AC1: JotLine のカード1枚・複数選択したカード・スレッドを、別ファイルのエディタ（ソースモード、ライブプレビュー）の任意の位置へドロップすると、その位置に既存の Markdown コピーと同じ内容が挿入され、JotLine 側からは削除される（Obsidian 上で手動確認）。
- [ ] AC2: AC1 で Ctrl（Windows / Linux）または Option（macOS）を押してドロップすると、挿入だけが行われ、JotLine 側のカードは残る（Obsidian 上で手動確認）。
- [ ] AC3: エディタで選択したテキストを別ファイルの JotLine ビューのタイムラインへドロップすると、ドロップ位置に1枚のカードとして追加され、元のノートからは選択範囲が削除される。修飾キーを押していれば、元のノートのテキストは残る（Obsidian 上で手動確認）。
- [ ] AC4: JotLine のカード（1枚・複数選択）とスレッドを、別ファイルの JotLine ビューへドロップすると、スコープの表のとおりに追加され（スレッドは同名のスレッドとして、ドロップしたグループの直後）、元のビューからは削除される。修飾キーを押していれば元は残る（ドキュメントへの追加・削除の処理は単体テストで、画面上の動作は Obsidian 上で確認）。
- [ ] AC5: JotLine のカード・スレッド、エディタの選択テキストをメイン入力欄にドロップすると、同じファイル由来のものも含めて、入力欄にテキストとして挿入される。JotLine のカード・スレッドは修飾キーに関係なく元が残る。エディタの選択テキストは、修飾キーなしでは元のノートから削除され、修飾キーを押していれば残る（Obsidian 上で手動確認）。
- [ ] AC6: ドラッグの元とドロップ先が同じファイルの場合（JotLine ビューと同じファイルのエディタの間、同じファイルを開いている別々の JotLine ビューの間）は、エディタまたは JotLine ビューのタイムラインへドロップしても何も変わらず、ドロップできない旨が通知される。メイン入力欄へのドロップは対象外（AC5 のとおり挿入される）（Obsidian 上で手動確認）。
- [ ] AC7: 移動したあと、JotLine 側の変化は JotLine のアンドゥで、エディタ側の変化はエディタのアンドゥで、それぞれ元に戻せる（JotLine 側は単体テストで、両側の動作は Obsidian 上で確認）。
- [ ] AC8: ドロップ先への追加に失敗した場合は元が削除されない。元の削除に失敗した場合は通知が出て、ドロップ先には追加された内容が残る（JotLine 側の処理は単体テストで確認）。
- [ ] AC9: 同じ JotLine ビューの中でのカード並び替えと、入力バーへの画像ファイルのドロップが、これまでどおり動作する（Obsidian 上で手動確認）。
- [ ] AC10: 既存の操作の挙動とデータフォーマットが変わらない。`npm run build`、`npm test`、`npx tsc --noEmit` がすべて成功する。
