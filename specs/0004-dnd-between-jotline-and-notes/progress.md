## 2026-10-20

### 作業ログ

- Spec を作成した（requirements → design → tasks の順に、それぞれユーザーの承認を得た）。

### 判断とその理由

- **移動とコピーの切り替え**: 既定は移動、ドロップ時に Ctrl（Windows / Linux）または Option（macOS）でコピー（ユーザーの選択）。OS のファイル操作と同じ慣習で、要望の「移動」を基本にするため。
- **同じファイルどうし**: ドロップさせない（ユーザーの選択）。JotLine の全体上書き保存とエディタの保存がぶつかり、内容が壊れるおそれを確実に避けるため。同じ JotLine ビューの中での既存の並び替えだけは例外として残す。
- **JotLine ビュー同士**: 別ファイルを開いている JotLine ビュー同士の D&D も対象に含めた（ユーザーの選択）。スレッドは同名のスレッドとして、ドロップしたグループの直後に追加する（ユーザーの選択）。
- **エディタへのドロップ**: スレッド名は挿入しない（ユーザーの選択）。既存の Markdown コピーと結果をそろえるため。
- **エディタの選択テキスト**: 選択範囲全体を1枚のカードにする（ユーザーの選択）。
- **メイン入力欄へのドロップ**: 常にテキストとして挿入するコピー（ユーザーの選択）。
- **複数選択とスレッドのドラッグ**: 選択中のカードの1枚をドラッグすると選択中の全カードを対象にする。スレッドはスレッドヘッダーをドラッグする。同じビューの中で複数選択・スレッドをまとめて並べ替える機能はスコープ外。
- **アンドゥ**: 移動のあとは、JotLine 側は JotLine のアンドゥ、エディタ側はエディタのアンドゥで、それぞれ戻す。両側をまとめて1回で戻すことはスコープ外。
- **モバイル版**: 動作を保証しない（機能を無効にはしない）。タッチ操作では HTML5 の D&D がほぼ動作せず、修飾キーも使えないため（ユーザーに説明のうえ、そのままで了承）。
- **実装方式**（design）:
  - ドラッグ中の情報は `src/dnd.ts` のモジュール変数で共有する（全ビューが同じ JavaScript 環境で動くため）。
  - エディタへの挿入はエディタの標準動作に任せ、挿入後の内容に含まれることを確かめてから元を削除する。位置まで確かめるには CodeMirror の内部 API が必要になるため。
  - `editor-drop`（Obsidian 1.1.0 以降）を使うため、`minAppVersion` を 1.1.0 に上げる。
  - 他のアプリからのテキストのドロップは何もしない（スコープ外）。
- **tasks の構成**: design は実機で未検証の前提に立つため、JotLine → エディタを実装した段階（Task 4）で一度 Obsidian 上で確認し、前提が崩れていれば design を相談してから残りを実装する。
