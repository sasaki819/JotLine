# aico-doctor

## 目的

AIco 環境の整合性を一括診断し、検知された問題点と具体的な修復手段を人間へ提示・実施する。

## 入力

* なし（任意で `--strict` の利用や修復方針の指定を受け付ける）

## 前提条件

* リポジトリ内に `aico-manifest.json` および `scripts/doctor.py` が配置されていること。

## 手順

1. 推奨ワーカー（`worker-low`）またはメインセッションで `doctor.py` を実行する。
   ```bash
   uv run <管理ルート>/scripts/doctor.py --json
   ```
   サブエージェントワーカーへ委譲する際は、親セッションの会話履歴が引き継がれない前提で、必ず以下の5項目をプロンプトへ明示する。
1. 参照する手順書・スキルパス
2. 対象範囲（ファイル・調査対象・比較基点コミット等）
3. 入力条件・制約（前提条件・対象外・守るべき規約）
4. 変更可否（読み取り専用か、許可する編集範囲はどこか）
5. 期待する成果と報告形式（出力先パス・実行環境・未確認事項を含む）
2. 全7カテゴリ（実行環境・マニフェスト／ワーカー設定・コンテキスト／配置構造・スキル／ワーカー同期・マーカー整合・記録／frontmatter／状態／相互参照・一覧鮮度／リンク／Markdown構造）の結果を `OK` / `WARN` / `ERROR` 別に整理する。
3. `ERROR` または `WARN` がある場合は原因と具体的な修復コマンド（`sync_agents.py`、`rebuild_indexes.py`、マニフェスト更新等）を人間へ提示する。
4. 人間の承認を得たうえで修復を実行し、再度 `doctor.py` を実行して解消を確認する。なお、検査で終了コード `1` となった項目を手作業で迂回してはならない。

## 完了条件と状態更新

* 診断結果と推奨対処が明確に報告されていること（修復実施時は再診断結果を含む）。
* 記録のステータス変更は行わない。

## 報告形式

* 検査カテゴリごとの `OK` / `WARN` / `ERROR` 一覧
* 検出された問題の詳細と推奨修復コマンド（または実施した修復と再診断結果）
