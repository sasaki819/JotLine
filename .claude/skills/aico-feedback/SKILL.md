# aico-feedback

## 目的

適用先プロジェクトの運用中に検知した AIco 本体の問題点や汎用改善要望を、AIco 開発者へそのまま共有・連携できる構造化 Markdown として出力する。

## 入力

* 検知した問題・改善要望の要点（任意で該当スキル名・スクリプト名・エラー内容・関連ログ等）

## 前提条件

* 具体的な外部連携手段（Issue 登録ツール等）には依存せず、連携用 Markdown の出力に徹する。

## 手順

1. 対象事象が発生した工程・スキル・スクリプトを確認し、`<管理ルート>/aico-manifest.json` から導入済み AIco の版（`aico_version`）と利用ツール（`tools`）を補完する。
2. 必要時（大量ログ抽出や構造原因の深掘り時）は `worker-low` または `worker-high` へ委譲して整理する。  
   サブエージェントワーカーへ委譲する際は、親セッションの会話履歴が引き継がれない前提で、必ず以下の5項目をプロンプトへ明示する。
1. 参照する手順書・スキルパス
2. 対象範囲（ファイル・調査対象・比較基点コミット等）
3. 入力条件・制約（前提条件・対象外・守るべき規約）
4. 変更可否（読み取り専用か、許可する編集範囲はどこか）
5. 期待する成果と報告形式（出力先パス・実行環境・未確認事項を含む）
3. 適用先プロジェクト固有の業務機密・個人情報・認証情報・内部ホスト名等が含まれないよう、必要に応じて一般化・マスクする。
4. 以下の項目を含む Markdown 形式で出力する（`aico-markdown-write` の規約に準拠）。
   * タイトル
   * 適用先プロジェクト名（および `aico_version`・利用ツール名）
   * 状況
   * 期待した動作
   * 実際の動作
   * 再現手順
   * 改修提案（任意）

## 完了条件と状態更新

* 機密情報を除外した構造化 Markdown ブロックが出力されていること。
* リポジトリ内の状態変更は行わない。

## 報告形式

* そのまま転記・連携できる Markdown ブロック（または整形済み Markdown）として出力する。
