# aico-archive

## 目的

完了・廃止済みの管理記録を各区分の `archived/` へ移動し、管理ルート配下の相対リンク追従と一覧再生成を安全に完了する。

## 入力

* アーカイブ対象の記録 ID またはパス（Runbook 実施記録は `<runbook>/<record-id>`、一意な `<record-id>`、または相対パス）

## 前提条件

* 現在の Git ブランチが `aico-manifest.json` の `integration_branch` であること。
* 対象記録がアーカイブ可否基準を満たしていること。
  * 議事録・チケット・Runbook 実施記録：`status` が `done` または `cancelled`。
  * ADR：`status` が `deprecated` または `cancelled`（`accepted`・`open` は不可）。
  * Runbook 手順書：配下の `records/` に `status: in-progress` の実施記録が残っていないこと。

## 手順

1. 推奨ワーカー（`worker-low`）またはメインセッションで、`--dry-run` を実行して移動先とリンク影響範囲を確認する。
   ```bash
   uv run <管理ルート>/scripts/archive_record.py --target <対象> --dry-run --json
   ```
   サブエージェントワーカーへ委譲する際は、親セッションの会話履歴が引き継がれない前提で、必ず以下の5項目をプロンプトへ明示する。
1. 参照する手順書・スキルパス
2. 対象範囲（ファイル・調査対象・比較基点コミット等）
3. 入力条件・制約（前提条件・対象外・守るべき規約）
4. 変更可否（読み取り専用か、許可する編集範囲はどこか）
5. 期待する成果と報告形式（出力先パス・実行環境・未確認事項を含む）
2. 移動元・移動先パスおよび書き換え対象の外部・内部リンク件数を人間へ提示し、実行承認を得る。
3. 人間の承認後、本実行を行い `archived/` への移動・双方向相対リンク追従・一覧再生成を一貫実施する。
   ```bash
   uv run <管理ルート>/scripts/archive_record.py --target <対象> --json
   ```
4. 終了コード `0` を確認し、必要に応じ `doctor.py` でリンク切れがないことを確認する。

## 完了条件と状態更新

* 対象記録が所定の `archived/` 配下へ移動し、被参照リンク・内部リンクおよび各区分一覧・ダッシュボードが更新されていること。
* 記録自体の `status` は変更しない。

## 報告形式

* 移動元パスおよび移動先パス
* 更新した外部リンク・内部リンク件数
* 一覧再生成の結果
